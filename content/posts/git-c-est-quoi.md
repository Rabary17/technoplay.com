***Tu modifies ton projet, ça casse, et tu ne sais plus ce qui a changé. Git est l'outil qui garde la trace de chaque modification, pour revenir en arrière quand c'est nécessaire.***

<div class="essentiel">

**L'essentiel en 30 secondes**

- Git enregistre l'historique des modifications d'un projet, étape par étape.
- Chaque enregistrement s'appelle un commit, et il porte un message qui le décrit.
- Git sert aussi à travailler à plusieurs, sans écraser le travail des autres.

</div>

Git est un système de gestion de versions. Il ne sauvegarde pas seulement ton projet : il garde la mémoire de ses changements. Tu peux comparer deux versions, ou restaurer un fichier tel qu'il était la veille.

## Les idées clés

Un dépôt est le dossier suivi par Git. Un commit est un instantané du projet, avec une description. Une branche est une piste de travail séparée, pour tester une idée sans toucher à la version principale. Tu peux ensuite fusionner la branche si l'essai est concluant.

<div class="exemple">

**Un exemple concret**

Un étudiant écrit son rapport. Avant de réorganiser complètement le plan, il fait un commit. Si la nouvelle version est moins bonne, il revient en arrière en quelques secondes. Le même principe s'applique à un site web ou à un programme.

</div>

<div class="attention">

**Ne mets pas de secrets dans un dépôt**

Un mot de passe ou une clé d'accès enregistrés dans l'historique restent visibles. Si cela arrive, change immédiatement le secret concerné.

</div>

<div class="lexique">

**Les mots à connaître**

- **Dépôt** : dossier de projet suivi par Git.
- **Commit** : enregistrement d'une étape du projet, avec son message.
- **Branche** : piste de travail séparée, pour tester une idée.

</div>

## Questions fréquentes

### Faut-il utiliser des commandes ?

Git fonctionne surtout par commandes, mais des interfaces graphiques existent. Commence par quelques commandes de base, pour bien comprendre la logique.

### Git est-il réservé aux développeurs ?

Non. Il sert aussi aux rédacteurs, aux chercheurs ou à toute personne qui modifie un document à plusieurs versions.

### Git et GitHub, c'est la même chose ?

Non. Git est l'outil qui gère l'historique. GitHub est un service en ligne qui héberge des dépôts Git.
